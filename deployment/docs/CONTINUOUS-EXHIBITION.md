# 持续展演修复 · 2026-09-10

现场要求：正式三屏展演持续运行，直到工作人员按 Ctrl+Shift+S 或点击 STOP SHOW。
保留 90 秒循环、音色和混音、显示映射、相机可选以及既有停止清理流程。
Ctrl+Shift+S 在正常清理后关机；STOP SHOW 仅停止展示。
本次读取到活动混音 Wind +6 dB、Instrument -6 dB，原样保留；不恢复较早的 -2 dB 快照。

## 根因

2026-09-10 本地时间 12:09 左右启动的场次，声音在 13:09:53 以
`reason=duration` 正常清理；13:12:17 外层以 `show-wrapper-timeout` 结束视觉控制器。
部署配置原为 3,600 秒，外层另加 120 秒等待。这是此前排练时限进入正式入口，
不是 Windows 计划任务到时结束；该任务的 ExecutionTimeLimit 已核对为 PT0S。
原始证据保存在外部 `incident-duration-limit-20260910T070217843Z`，没有删除旧部署。

此外，真实光标和鸟群桥接的经过时间验证也限制在一小时。只取消外层时限会使画面
继续而声音输入失效，因此本次同时更新发送端与接收端的时间范围。

## 最小修复与身份

- 正式配置 `durationSeconds: 0` 表示持续到 Stop；有限排练的 1–3,600 秒模式保留。
- 外层、声音发送端、SC 及其 Windows 作业所有者不创建持续模式总时长定时器。
- 真实光标和鸟群经过时间接受至 JavaScript 安全整数毫秒上限；协议字段、短期新鲜度、
  心跳、序号限制和 Stop 后拒绝输入均保留。
- 持续服务日志仍截断至原有有限大小；流量保护改为每秒预算，避免周期诊断累计触发退出。
  持续静音验证不录制无界 WAV。未新增声音服务、调度器或自动重启机制。
- JanVim 产品 artifact 不变；控制器 bundle 为 556446 字节，SHA-256
  `ffdc4e82119206ad07ef7079cce0b677d22fa93f8263978f7e69a51a8dcbf08f`。
- 《见山》源码 `740c17c9b7e799e90fe5d5d9d17aed4ece513d4e`，基于现场
  `6d1a4577a9484092fde94308352c80ee710ed18f`；候选 EXE 为 9818112 字节，SHA-256
  `07d0ba1cbdba692fe4919476799219d698ce11469be5abb5f954a561c8dfb526`。
  只更新桥接时间边界，不改变鸟群、风声、TOML 或模型。

## 验证与回退

新测试先证明原实现会在旧时限失败，再用假时钟覆盖一小时、24 小时之后的输入与停止。
持续 SC 静音启动及显式 Stop 清理已有实际测试。原生桥接 69 项、混音 8 项测试与
离线 release 构建通过；Rust 格式组件不可用，未把它记为通过。
最终自动验证、完整包身份和安装状态见本次外部 `continuous-show-20260910` 回执。

这些测试不代表已完成长时间物理展场验收。仍需观察本候选实际跨过旧的一小时与
62 分钟退出点，以及三圈、离线与强制重启项目；不得用假时钟替代现场记录。

固定部署目录整体保留后再切换已校验的新包，不零散覆盖。回退时先正常 Stop，再由
技术人员整体恢复保存的旧目录并执行 Verify-Deployment。旧版本仍具有一小时限制，
仅作为既有可运行版本保全，不能满足本次持续展演要求。
