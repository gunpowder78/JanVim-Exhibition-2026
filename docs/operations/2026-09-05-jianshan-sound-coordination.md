## 建议协作边界

- 《见山》负责从实际正在显示的模拟状态提取有界聚合特征；不要发送逐鸟数组，不在帧循环等待声音 ACK。
- 第一版只讨论活动能量 `energy` 和归一化横向重心 `centroidX`。两者的归一化、空鸟群语义和采样时点需双方书面约定，不能把鸟数直接当活动能量。
- 生产端采样建议不超过 20 Hz，背压时只保留最新状态，不积压或补播。应带生产端身份、递增序号和单调采样时间，具体传输格式待双方确认。
- 若有 GPU 模拟路径，必须取权威的实时状态/聚合结果；不得把没有同步的旧 CPU 鸟群数组当成当前画面。
- 声音端唯一 sender 负责 OSC session、跨事件的全局序号、接收端时钟换算和 Stop。不要让两个应用各自生成同一声音 session 的序号，也不要让鸟群流量代替展演存活心跳。
- 项目级 OSC 接收器已有 `/janvim/sound/v1/flock`，参数为公共 session/seq/sentAt 后接 energy/centroidX；这不是要求《见山》直接向 SuperCollider 发包。实际接入层需协商后再冻结。
- 现阶段仅本机回环通信，不引入跨机部署。声音失效不能阻塞鸟群画面。既有《见山》声音若也开启，需明确关闭或混音所有权，防止重复风声。
