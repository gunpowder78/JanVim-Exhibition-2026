## 结论与方案取舍

同意“权威状态聚合 → 本机生产入口 → JanVim 唯一声音 sender → SuperCollider”。推荐复用声音进程已有的回环 TCP / NDJSON 入口，新增隔离的鸟群生产者角色；不是占用现有光标 owner，也不是要求贵方改掉独立试听 OSC。

| 方案 | 取舍 |
| --- | --- |
| 复用本机 TCP / NDJSON 入口（推荐） | 沿用已有监听、认证、消息长度限制和挂接时钟；Rust 增加一个有界后台发送器，不新增服务或固定端口。 |
| 新增 UDP / OSC 鸟群入口 | 可复用贵方 OSC 编码，但我方需新增入口、解码、身份绑定及时间锚定；若贵方 TCP 接入成本明显更高，可再共同选此项。 |
| 《见山》直接发送最终声音 OSC | 不采用，会绕开唯一 sender 的 session、全局序号及 Stop 所有权。 |

现有声音 TCP 目前仅接纳一个光标生产者，**并未具备第二个鸟群角色**。本建议是下一独立小任务，不混入正在收尾的真实光标接入。外部入口采用 NDJSON 不影响 sender → SC 继续使用 OSC；[SC 官方说明](https://doc.sccode.org/Guides/OSC_communication.html)也将 OSC 的传输与消息协议区分开来。

## 1. 入口、端口和权限

- 只绑定 `127.0.0.1`。沿用当前声音服务由操作系统分配的 TCP 端口；**不预先硬编码一个“永远可用”的端口**，不向 SC 的 57140 / 57141 直接发送鸟群数据。
- 后续实现时，声音启动器在当次外部运行目录生成独立的私有 `flock-input.json`，字段建议为 `version=1, active, host, port, protocol="jianshan-flock-ndjson-v1", token`。它与控制器控制回执共享监听端口，但 token 独立，仅授权鸟群输入，无权 Stop、续展演租约或接管光标。
- 操作员明确把该文件路径交给《见山》；不扫描“最新”运行、不自动启动 SC。未配置、文件失效或端口不可用时，鸟群画面照常运行，声音入口保持禁用。
- 一个声音运行最多绑定一个鸟群源，一条连接。连接和发送放在帧循环之外；首次挂接有界超时，不自动无限重连。换进程或断线后的重新挂接首版由技术人员重新启动本次联动处理。

## 2. 建议字段与时间基准

挂接帧建议：`version, command="attach-flock", token, sourceId`。`sourceId` 为每次鸟群进程创建的 32 位小写十六进制随机串；token 为回执中的 64 位小写十六进制私钥，不进入遥测日志。接收方确认挂接后，数据帧不逐条 ACK。

| 字段 | 类型与含义 |
| --- | --- |
| `version`, `command` | 整数 `1`，固定字符串 `"flock"` |
| `sourceId` | 与挂接身份完全一致；不是最终 OSC session |
| `seq` | 正 int32，递增、可跳号；reset 不归零 |
| `epoch` | 正 int32，初始 1；软重置、后端切换或设备重建使统计失效时递增 |
| `sampledAtMs` | 有限 float64；距收到挂接确认的单调毫秒数，不是 UTC 或帧号 |
| `state` | `"sample"`、`"empty"` 或 `"unavailable"` |
| `energy`, `centroidX` | 仅 `state="sample"` 时提供，有限数值 `[0,1]`；发往最终 SC 时由唯一 sender 编码为 float32 |

连接认证后身份绑定在连接上；后续不重复传 token。NDJSON 每帧最多 1024 UTF-8 字节（不含换行），严格字段集；不发送逐鸟数组。首版建议 10 Hz、硬上限 20 Hz，最新值覆盖，丢弃而非补播。后台发送器最多一条进行中的编码帧及一个最新状态；部分 TCP 写入必须先正确处理当前帧，不能把两条 JSON 字节拼坏。长时间背压直接禁用鸟群声音，不阻塞绘制。

时间不用跨进程直接比较 Rust `Instant` 和 Node 的原始值：接收方在确认挂接前记自身单调锚点，生产方在收到确认时记自身零点。接收方以“自身当前时间 − 挂接锚点 − sampledAtMs”保守估计年龄；确认传输延迟只会使估计更旧。超过 500 ms 丢弃，终端 sender 发送前再检查，不能在每次转发时重置样本年龄。

GPU 的 sampledAtMs 记录目标模拟/聚合任务提交的时间，**不能填异步回读完成时刻或网络发送时刻**。回读结果必须带原 epoch 和采样时间；挂接前的结果不转发。若挂接延迟使全部结果被保守判旧，禁用该次鸟群输入并报告，不放宽检查或自动“校准”为新数据。双方实施测试还需覆盖单调时钟异常及进程长时间停顿。

## 3. 聚合语义建议

建议 energy 首版表达“模拟运动强度”，不声称是屏幕像素/秒，也不额外差分两次位置。定义：

`energy = clamp(mean(length(velocity)) / vRef, 0, 1)`

逐鸟先取速度模再求均值，不用平均速度向量的模，不用鸟数代替。`vRef` 使用固定、可复现的参考尺度；请贵方返回当前 GPU/CPU 速度单位及建议数值，再冻结。若两后端单位不同，必须显式换算或分别记录固定参考，不能运行中自动拉伸音量。

建议 centroidX 为“全部活动鸟投影到画布的算术横向重心”：`mean(clamp(x / 1000, 0, 1))`。越界鸟投影到边缘，回绕使用该采样时刻实际绘制的位置；不使用环形均值，不把左右两端集群解释成画布外的重心。它不等于仅可见鸟的重心；若贵方画面意图要求后者，应在冻结前改选。

为控制 GPU 修改量，首选固定均匀索引抽样，`K=min(activeCount,1024)`；索引 `floor((k+0.5)*activeCount/K)`，`k=0..K-1`。以上 mean 在同一批样本上计算，诚实标记为全体活动鸟的估计，不是全量精确统计；不引入逐帧随机抽样。若现有布局使全量归约反而更简单，可由贵方提出替代，但不回读 20 万条鸟记录。

从“本轮模拟更新后、用于该轮绘制的活动缓冲”读取；聚合可在同一提交序列中完成，回读使用独立小型 staging buffer，最多一个采样在途，未完成就跳过下一采样。不要映射正在绘制的活动缓冲或等待 readback。异步完成只代表对应已提交状态，不宣称取到了尚未提交的下一帧。[wgpu Buffer 文档](https://docs.rs/wgpu/latest/wgpu/struct.Buffer.html)说明映射期间缓冲不可同时供 GPU 使用；实际 API 须以贵方锁定的 wgpu 版本为准，不为协作升级依赖。

CPU 路径使用本轮更新后的真实状态，采用相同抽样与投影规则；GPU 路径不使用未同步的 CPU 数组。接口冻结前由贵方确认这些点是否能小范围实现及其测量开销。

## 4. 失联、reset 与统一 Stop

- 仅收到有效鸟群数据不允许自行发声：必须同时存在本次有效 Show 授权/心跳，且统一 Stop 尚未锁定。鸟群输入不能续展演租约。
- 500 ms 无新鲜 sample，或收到 `empty/unavailable`、连接关闭时，只淡出风声，拨弦继续。未完成 readback 不伪造 empty/energy=0；不必每帧发 unavailable，状态变化可立即报告，其余由新鲜度超时兜底。
- 已核实当前 `jvWind` 在 energy=0 时仍有 0.015 的幅度基线，因此不能把“发零能量”当静音。后续我方需增加独立的风声关闭动作，优先复用现有 gate 的约 0.3 秒释音，不重写音色。
- 同一连接的短暂采样缺失恢复后，仅在 Show 仍有效、没有统一 Stop、epoch 合法时允许风声平滑回来；这不是解除 Stop。鸟群进程断线首版不自动重新绑定。
- epoch 增加后抛弃全部旧回读和待发状态，清除旧风声目标；新 epoch 的真实 sample 到达后再恢复。软 reset 不重建全局 OSC session、不归零 seq，不触发统一 Stop。
- Stop Show、Show 心跳失联及既有终止条件仍由声音唯一 sender 执行统一 1.5 秒淡出和锁定；迟到鸟群数据、重置、新 epoch 均不得重新发声。新的声音运行必须重新显式启动。
- 当前没有可操作零鸟状态也可以先实现协议中的 empty 语义与确定性测试：empty 不含 energy/centroidX，不把空集合重心臆造为 0 或 0.5。
- 联合试听关闭《见山》内置声音及独立 SC 风声服务，不动原配置保底；由技术人员显式选择联动配置。
