# 真实逻辑光标拨弦：独立声音启动接入设计

日期：2026-09-05。状态：书面设计待用户审阅；尚未实现真实输入。

- 起点：已保全声音提交 `cbde651840805ca1ae8d0a540ea5dac0a05a4056`。
- 保留 `feat/sound-minimal-loop` 与既有可展览工作树，不切换它们的分支，不改动其中的文件。
- 不编译或替换 JanVim 产品，不修改 artifact lock、原诗、长文 profile、显示配置、配色或用户 Neovim 配置。不推送、合并或替换里程碑标签。
- 允许在候选内修改展演 Lua、控制器可选接口、声音输入适配与对应测试；控制器改动需要重新构建 Electron bundle，并记录其新哈希。

## 方案取舍

采用“独立声音进程 + 可选的真实输入”。操作者先启动声音，再显式把该次声音运行目录交给展演。默认展演仍完全无声且不依赖 SuperCollider。

不选“展演启动器自动启动和重启 SuperCollider”：这会扩大进程所有权、启动失败和自动恢复的修改面。也不选“只把整条编辑命令的 ACK 当光标轨迹”：长文内的实际移动会被压缩成少数事件，不能代表连续写入。

## 操作与数据流

1. 为 `sound/start-sound.ps1` 增加显式真实光标输入选项；保留当前模拟输入为默认。听音仍必须显式 `-Listen`，默认仅无声诊断。现有运行时长和录音上限保持不变。
2. 真实输入模式 READY 后等待一个展演控制器绑定；不运行模拟光标或模拟鸟群时间线，不凭空播放风声。
3. 候选 `start-show.ps1` 增加可选 `-SoundRunRoot`。只接受明确指定的、外部演练目录中的当次活动声音运行。没有该参数时保持现有路径；不扫描“最新”声音目录或自动接管其他声音会话。声音目录/回执无效或服务已退出时，只禁用可选声音并给出诊断，不因此拒绝启动画面。
4. 展演 Lua 在自身 scratch buffer 中观察已发生的光标移动。数据经现有认证桥的独立、可选 `cursor` 消息类型交给控制器；它不是命令 ACK，不完成或改变编辑命令。
5. 控制器经声音现有的本机认证控制连接提交特征。声音侧唯一 sender 继续负责 SuperCollider session、全局 OSC 序号与接收端时钟换算；Lua 不直接控制 SuperCollider。

这次不新增 HTTP 服务、消息中间件、设备 GUI 或远程网络入口。声音控制连接只绑定 `127.0.0.1`；保留每次运行的私有 token，不将其写入共享回执或协作备忘。

## 真实光标与乐句

- 仅观察本次展演的 move、insert、select 动作实际产生的坐标变化；不使用键盘注入、不读取其他编辑缓冲区、不上传文本。
- 坐标是 Neovim 逻辑行与显示单元列。UTF-8 字节偏移不得直接当汉字列宽；不声称它等于剑客核心、粒子或物理像素轨迹。
- 使用窗口内逻辑位置生成归一化 x/y；竖排的横向对应逻辑行方向。移动强度使用原始逻辑坐标差计算，避免滚动或归一化分母变化制造虚假跳跃。
- 沿用已试听的五声音阶拨弦、响度限制和音色；坐标影响既有音高/声像映射，实际移动幅度与间隔影响触发和力度，不新增作曲器或随机演奏时间线。
- 无实际坐标变化不触发。prepare、reset、首次位置及恢复后的基准位置只重建参考，不把回到原诗的跳跃当作一记强音。
- 源端和声音接收端均限制最多 8 次/秒；一处最多保留一个最新待发样本，超过 0.5 秒直接丢弃，不补播积压音符。不增加编辑命令重试。

## 生命周期与失败隔离

- 同一次声音运行只绑定一个控制器 run identity；所有观测还需匹配当前 generation、loop/cue 与递增源序号。旧进程、旧循环或重复消息不能触发声音。
- 认证桥保留原有 ACK 语义和容量上限。合法消息帧中的可选观测有单独严格 schema、长度和速率上限；观测字段解析失败或监听器异常只丢弃该观测，不拒绝当前编辑命令。未认证来源不能使用观测入口。原有连接级认证、非法 JSON、超长帧和资源滥用防护不削弱；这不是让损坏的主通信继续运行。
- 声音连接和发送均不进入 cue 的等待链；连接失败、背压或声音进程退出时记录有界诊断并关闭可选声音路径，展演继续。新增客户端至多一个连接、一个最新样本和有限计时器，结束时全部释放。
- 绑定前声音服务保持静默等待，受原有最大运行时长约束。绑定后由展演存活心跳决定声音租约，声音 sender 不得自行伪造展演仍存活的心跳。
- 正常循环 reset 清空光标参考后继续下一循环，不等同于终止声音。
- Stop Show、展演终止或控制器失联触发现有统一停止机制：1.5 秒淡出；失联先受现有 2 秒租约超时约束。Stop 后锁定，不被迟到的光标或心跳唤醒。
- 本轮保守处理 JanVim 进程故障：终止该次声音会话，视觉系统仍按既有策略恢复。声音不自动重启；需要操作者开启新声音运行及新展演。这一限制避免把音频恢复工程混入首次真实输入接入。

## 实施验证与交付标准

先增加失败测试，再改变运行行为。假单调时钟覆盖：实际移动与静止、中文列宽、8 Hz 限频、单槽丢弃、reset 不误触发、旧 generation/序号拒绝、声音掉线不影响 ACK/视觉、Stop 锁定和监听器/计时器释放。

自动验证应包含真实 Lua 坐标观察到 sender 的链路、声音不可用的视觉回归，以及 SuperCollider 无声录音的触发与停止证据，不能只注入合成坐标就声称真实光标接入通过。完整验收前运行仓库要求的 npm ci、typecheck、全部应用测试、build，另加 lint、Lua、声音测试和 runtime 校验；记录候选 bundle SHA-256，并核对原保底身份未变。

人工窗口只检查：长文真实写入与拨弦相关、静止不乱响、一次 reset 后可继续拨弦、Stop 平滑结束且不再响起；同时确认配色、标点、列距和恢复原诗未变化。新的联动验收不冒充真实投影或现场音响验收。

本设计不承诺零风险。回退方式是停止候选，使用未修改的原展演工作树；原独立模拟声音也保持可用。
